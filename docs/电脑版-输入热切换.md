# 电脑版输入热切换

版本：2026.9.29.1。键盘、鼠标热区与手柄可以直接换用，不必每次换设备都到设置里关闭另一种跟随。

## 第一次准备

1. 绑定游戏窗口，选好配音章节、小节，确认播放器当前句与游戏一致。
2. 使用鼠标时，先设置「下一句」点击热区并开启点按跟随。
3. 使用手柄时，到「手柄」页勾选「用手柄跟随游戏对白」，选择游戏实际使用的继续键。升级会沿用原设置：以前关闭的不会自动开启，仍需首次勾选。
4. 收起面板后按游戏继续键，或在热区轻点。换设备前先松开上一设备，不要同时按两种设备。

手柄启用并在线时，键盘和鼠标仍可推进配音。键盘单键、手柄归中、鼠标完整轻点以及对白检查的原有规则继续生效；热切换不会绕过暂停、分支待选或需要核对当前位置的状态。

## 当前来源怎么看

设置中的「键盘 / 鼠标 / 手柄自动切换」显示「自动切换 · 当前：键盘／鼠标热区／手柄」，尚未记录输入时显示「等待输入」。它随有效的跟随输入更新，移动鼠标、闲置手柄的状态刷新不会抢走当前来源。

这个提示记录的是输入来源，不是游戏已经换句的证明。鼠标按下进入观察后，仍要等完整轻点松开确认；开启对白检查时，还要通过画面变化判断。时间相近的输入被关联到手柄时，提示也可能改为手柄。

重新绑定游戏、换配音包或主动确认／定位当前位置时，软件会重新建立跟随记录，清除旧来源关联和未完成的鼠标轻点。早于这次记录的旧推进输入不会拿来补走新位置；如果处理输入时才发现游戏窗口或配音包已经变化，会暂停并要求核对当前句。

## 同一次操作尽量只跟随一次

Steam Input 或其他映射可能让一次手柄按压同时产生手柄、空格或鼠标消息。本版按时间尝试关联这些推进：

- 不同来源的输入相距不超过约 220 毫秒时，合并成一次跟随；键鼠先到或手柄先到均适用。
- 已登记的手柄继续键按住期间，键鼠推进暂不接管；松开后再保留约 220 毫秒关联时间，覆盖松开时才产生的映射消息。
- 普通重复消息不会不断延长窗口；手柄闲置时反复上报“没有按键”也不会一直挡住键鼠。
- 同来源的新按压仍交给原有跟随处理，不用这个窗口吞掉真实连续按压；开启对白检查时，连续快按仍可能因无法确认位置而停住。

鼠标保留按下、移动、松开的完整轻点检查。其长按、拖动与不足 300 毫秒连续轻点保护，和上面的跨来源 220 毫秒关联是两项不同规则。鼠标尚未松开又开始另一种独立推进时，可能暂停并要求核对，不能靠同时按两台设备加速。

进入本轮跟随判定的推进输入，如果从发生到处理已超过 200 毫秒，或时间异常，软件会暂停配音并提示核对，不按积压输入连续补走台词。游戏可能已经收到这些操作，请先核对游戏显示的当前句，再确认或重新定位。这里的 200 毫秒检查的是消息延迟，不是要求两次正常操作至少间隔 200 毫秒；它也不同于跨来源的 220 毫秒关联窗口。

这只是时间启发式，不能识别输入是否真的来自某个映射软件。两次很近的独立跨设备操作可能被合并；映射副本超过窗口才到达也可能重复。切换时先松开并稍停片刻；若需要严格避免多路推进，可停用多余映射，只保留原生手柄或映射为键鼠的一条推进路径。这个机制不会拦截游戏收到的输入，也不自动合并面板的所有确认操作。

## 手柄断开时

| 当时的操作 | 处理 |
| --- | --- |
| 当前使用键盘或鼠标跟随，手柄闲置 | 手柄断开、切设备或监听故障不暂停键鼠跟随 |
| 当前使用手柄跟随 | 手柄断开、切设备或监听故障会暂停，先核对游戏当前句 |
| 正在听书 | 闲置手柄变化不打断听书，听书进度与游戏位置保持独立 |

手柄重新连接或切回窗口后，先松开按钮、让摇杆归中。重连不会自动发声或补发旧按压；需要恢复时核对当前句后继续。

## 与其他模式的关系

游戏自动播放期间，键盘、鼠标或手柄的手动操作仍会先停止自动播放；热切换不会让自动点击接着跑，也不会补点。小台词条按钮仍只操作配音，听书时只操作听书。

桌面的 F9 单次 OCR 定位和「检查对白后再跟随（试验）」继续保留。热切换没有删除 OCR，也没有新增常驻 OCR 轮询。定位仍需核对候选；对白检查观察小区域图形变化，不识别具体台词。

本说明依据当前实现与隔离检查编写，不代表真实战双、实物手柄或各类映射软件已实测通过。详见[电脑版-手柄操作](电脑版-手柄操作.md)、[电脑版-跟随改进](电脑版-跟随改进.md)与[电脑版-自动播放与听书](电脑版-自动播放与听书.md)。
