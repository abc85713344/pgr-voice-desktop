# 播放器共享核心

`PgrVoice.Core.csproj` 使用 .NET 10，不引用 WPF、Win32、Android 或 OCR 原生库。Windows、Android 和核心测试均引用同一程序集。原有 7 个纯核心文件继续保留在 `src`，由共享工程链接编译，避免拷贝两套剧情规则。

## 自动跟随调用约定

所有 `PlaybackEngine` 操作和 `FollowSafetyController` 操作必须在同一个串行队列执行。OCR 可以在后台运行，开始时捕获 `Epoch` 和单调增加的截图 `Sequence`，结果回到串行队列后再进行判断。

1. 启动默认 `Manual`。`SetMode` 和 `Invalidate` 递增 `Epoch`、解除自动推进资格，不播放。
2. 手动切章、导航、暂停、原声、恢复存档、重新捕获授权前调用 `Invalidate`，让旧 OCR 失效。
3. 用户明确确认当前位置后，调用 `ConfirmPosition(engine, frameKey)`。它要求自动模式、当前是已允许路线内的台词、剧情模式为 `Following`。暂停状态可先由用户操作 `TogglePause` 静音恢复；不能在切换模式后未经确认就调用此方法。
4. `FrameKey` 是字幕像素摘要，不能用动画背景、截图时间或随机值。没有基准画面时可以不传，第一张稳定帧会被记录为基准，不推进。
5. 每个 OCR 结果构造 `FollowObservation`，调用 `Evaluate`。只有当前明确可达的下一句、完整文字精确匹配、OCR 置信度达标、连续两次有效结果一致时才返回 `Advance`。菜单、汇合、未核实边界、跳句和模糊文字交给候选。
6. 在同一队列上立即 `TryApply(engine, observation, decision)`；它再次核对会话和路线，然后内部调用 `engine.Next()`，调用方不要再次推进。
7. `TryApply` 只可成功一次。上一句画面不变时不自动重播；相邻两句规范化后文字相同，一律使用手动下一句，避免白色背景动画被误当作同文换句。仅有标点差异也按此规则处理。

冷启动或导入存档后为 `Ready`。用户明确确认后调用 `engine.ConfirmCurrentPosition()` 静音恢复推进资格，再调用 `follow.ConfirmPosition`；不要用 `ConfirmGameLine` 重复录入一次历史。前者保留未知单句的限制，不解除原声模式。

`CoreDiagnostics.Message` 由平台自行接入日志。日志失败不改变剧情状态。

## 可选共同线自动播放调用约定

普通自动跟随继续逐句核对 OCR，由玩家点击游戏。新增共同线自动播放仅在开始时 OCR：当前小节内唯一完整匹配，连续两次有效结果一致后确认起点；随后按已核实共同线顺序播放，不再逐句 OCR。Android 端自愿开启无障碍点击权限后，在自然播放结束时申请一次指定范围的触碰；系统手势完成后等待约 450 毫秒，再推进到预期共同下一句并播放。

`engine.EvaluateCommonAutoPlayNext()` 是新增只读接口，必须在同一串行队列调用：

- `CurrentIsCommon` 证明当前为已确认整句且属于共同线。共同线末句仍可返回 true，允许先听完本句。
- `Allowed` 与 `Next` 只在当前和直接下一句均明确为共同线、既有导航也允许此连接时给出点击资格；不跨 choice、merge、return、gap 或 end。
- 空 `PathId` 不是充分证据。门控排除选项入口、`SegmentIds`／`LineIds`／边界及从分支入口到出口前的图范围，再从小节入口和已核实共同汇合点建立共同链。无法确认的结构拒绝自动播放，归档旧图不参与当前范围。
- 首次 OCR 候选可由无监听的临时 `PlaybackEngine` 导入当前导航快照，再 `ConfirmGameLine` 和门控预审；检查两次返回值，不能让预审改动真实历史或发声。只有确认唯一共同候选后，实际引擎才确认并播放。

平台的 `AutoPlaybackCycle` 独立保存启用代次、音频票据和单次手势票据。自然完成不得由停止、暂停或重播的旧回调代替；只消费当前票据一次。成功手势须匹配代次、手势票据与预期下一节点，随后在短暂转场之后再复核共同线门控，才调用既有 `TryAdvanceAutomatically`。初次确认和顺序准备的 `TimedOut(now)` 由会话定时器处理；超时不补点。

下一步为分支时当前句播完提醒停止，分支内部禁止启用；缺音或不明连接同样停止。回到共同线后需要用户重新定位并手动开启。切章、导航、退出游戏前台、锁屏、旋转／折叠、屏幕捕获或无障碍权限失效均使本轮失效；环境恢复不自动恢复。点击范围绑定官服与物理显示配置；无障碍服务核对窗口和坐标，不读取界面文字。

由于中途没有 OCR，手势完成不等于游戏已换句。漏触碰、卡顿或手动跳句可能造成配音错位，用户应停止并重新定位，不能用重复点击追赶。核心门控不负责证明自然音频结束、实际触碰、前台窗口或游戏换句，这些由平台与设备回归分别验证。

## 字幕画面稳定门控

`SubtitleStability.Observe(byte[])` 接受 0/1 掩码，返回 `Changed`、`Stable`、`FrameKey`。首次画面或显著变化后，连续两次稳定观察才允许 OCR；少于 12 个白点的空白画面不视为稳定字幕。`Reset()` 不复用旧画面编号。

默认显著变化条件为：差异至少 8 像素，且差异占两帧白字并集至少 8%，或绝对差异达到 24 像素。24 像素兜底避免一个字的变化被大片白色区域稀释；1–3 像素采样抖动和 3 个噪点移位造成的 6 像素差异被忽略。基准缓冲复用，稳定帧无逐帧托管内存分配。

掩码只做门控，不能证明白点来自字幕，真实游戏背景去噪尚需素材和真机验证。普通自动跟随仍需要逐句完整 OCR 精确一致、两次有效结果、明确路线和旧会话失效检查；可选共同线自动播放只在开始定位时使用这一识别门槛。

## ZIP 导入与存储

`PackageRepository` 存放章节，`ProgressStore` 存放进度，二者目录独立。`ImportAsync` 接受系统文件选择器打开的 `Stream`，包括不可定位流；不会把整个 ZIP 或全部音频放进内存。

导入采用“磁盘临时文件 → 解压 → 配音包和实际音频校验 → 不可变 revision → 原子替换 current.json”。提交前取消或失败保留当前章节；提交点之后返回成功。中文文件名和旧包反斜线音频路径得到保留。拒绝 ZIP 越界、符号链接、大小写冲突、多个清单、缺失已绑定音频和超限大小。按需清理 `CleanAbandonedImports()` 只处理未提交的临时导入。

旧 revision 保留，因此正在播放的音频路径不会突然失效。导入不会改进度、历史或书签。更新后沿用 `ProgressStore.TryRestore`：音频变化保持兼容；剧情连接变化仍按现有导航指纹和迁移规则处理，静音恢复。
